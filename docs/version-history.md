### R59：一个值得记住的 bug

**现象**：某根弦松手后还在持续响。

**根因**：`paw3395_driver.v` 在读 Motion 寄存器时，若 bit7（MOT）= 0 表示「本轮无位移」，
原代码直接跳去读 SQUAL，**`delta_x/delta_y` 保留了上一次运弓的大值**；
而 `S_QUALITY_WAIT` 无条件置 `sample_valid<=1`，于是 tracker 每 2 ms 收到一个
「位移 = 旧大值」的假样本 → `sum_sat` 恒大于 `CLOSE_TH(12)` → gate 电平永不清零 →
那根弦一直响。哪根弦由 `pick_r`（常驻不清零）上次锁定的结果决定。

两条保底同时失效：8 ms 看门狗只在 `sample_valid==0` 时计时；R49 的 ready 冻结
又把 `!ready → gate<=0` 拿掉了。

**判据**：一次「松手还响」= 这个 bug，不是 hold 违例、不是显示、不是选弦逻辑。

## 一句话总结这 8 天

三次同型事故（R38、R44、R57）都指向同一条规律：
**在这个设计里，"给关键信号多加一个消费者" 比 "写错一行逻辑" 危险得多。**
R54 之所以是效果最好的版本，不是因为它功能最多，而是因为它**没有动那些信号**。
