# 烧录指南（ESP32）

本文只讲一件事：**怎么把编译出来的东西烧进 ESP32**。三种方式，按从省事到可控排列。

---

## 0. 先确认插的是哪个口

ESP32 开发板上有两个 USB：
1. **FT232 那个口**（板载 USB 转串口芯片）—— 烧录用这个；
2. 直连 ESP32 的 USB 口（若有）—— 本项目不用。

插上后设备管理器会出现一个 **USB-SERIAL CH340** 或 **Silicon Labs CP210x** 之类的 COM 口，记下 COM 号（例如 `COM5`）。

> 别和 Tang Mega 60K 板载调试器搞混：那个是 BL616，要按住 UPDATE 进 DFU 的是它，不是 ESP32。ESP32 烧录**不需要**按 UPDATE。

---

## 1. 烧录文件是编译时就生成的

执行 `pio run` 后，`.pio\build\esp32dev\` 下会有：

| 文件 | 偏移地址 | 作用 |
|---|---|---|
| `bootloader.bin` | **0x1000** | 二级引导 |
| `partitions.bin` | **0x8000** | 分区表 |
| `boot_app0.bin` | **0xe000** | OTA 选择标记（在 framework 包里，不在 build 目录） |
| `firmware.bin` | **0x10000** | 应用本体 |

`boot_app0.bin` 的位置（随 PlatformIO 安装，路径因人而异）：

```
%USERPROFILE%\.platformio\packages\framework-arduinoespressif32\tools\partitions\boot_app0.bin
```

**这四个文件就是全套烧录文件。** 平时 `pio run -t upload` 会自动按上表地址依次写入，你不用管地址。

---

## 2. 方式 A：PlatformIO 一键烧录（推荐）

```powershell
$env:PYTHONPATH=''                                  # 见下方说明，必须
cd "D:\applicationstudy\Fpga\GOwin\documents\Tang Mega 60K MUSIC\esp32_wifi_console"
pio run -t upload
pio device monitor
```

- `-t upload` 会先编译，再自动找串口写入。
- 串口若不唯一，加 `--upload-port COM5`。
- 看到 `Hash of data verified.` + `Leaving...` 就是成功了。

> **为什么要 `$env:PYTHONPATH=''`**：WorkBuddy 会往 `PYTHONPATH` 注入一个 shim 目录，SCons 结束时清理临时文件会被安全守卫拦截，导致明明编译成功却报 `Error 1`。清空这一项即可。用 VS Code 图形界面点编译不受影响。

如果用 VS Code：打开 `esp32_wifi_console` 文件夹 → 左下角 PlatformIO 图标 → `esp32dev` → **Upload**。

---

## 3. 方式 B：单文件合并包 → 烧到 0x0

适合存档、发给别人、或用第三方工具烧。

### 3.1 生成

```powershell
$env:PYTHONPATH=''
cd "D:\applicationstudy\Fpga\GOwin\documents\Tang Mega 60K MUSIC\esp32_wifi_console"
pio run -t mergebin
```

产出：

```
.pio\build\esp32dev\firmware_merged.bin
```

脚本会打印实际大小和 SHA256。等价的手工命令（若要自己拼）：

```powershell
py -3 "$env:USERPROFILE\.platformio\packages\tool-esptoolpy\esptool.py" `
  --chip esp32 merge_bin `
  -o firmware_merged.bin `
  --flash_mode dio --flash_freq 40m --flash_size 4MB `
  0x1000  .pio\build\esp32dev\bootloader.bin `
  0x8000  .pio\build\esp32dev\partitions.bin `
  0xe000  "$env:USERPROFILE\.platformio\packages\framework-arduinoespressif32\tools\partitions\boot_app0.bin" `
  0x10000 .pio\build\esp32dev\firmware.bin
```

### 3.2 烧写

```powershell
py -3 "$env:USERPROFILE\.platformio\packages\tool-esptoolpy\esptool.py" `
  --chip esp32 --port COM5 --baud 460800 `
  write_flash -z 0x0 firmware_merged.bin
```

**起始地址必须是 `0x0`**，不是 `0x10000`——合并包内部已经是完整镜像布局。

## 4. 方式 C：Flash Download Tool（Windows 图形界面）

适合不想碰命令行、或给别人演示。

1. 下载乐鑫 **Flash Download Tools**（`flash_download_tool_*.exe`），解压运行；
2. ChipType 选 **ESP32**，WorkMode 选 **Develop**，点 OK；
3. 只填一行：
   - 文件：`firmware_merged.bin`
   - 地址：**`0x0`**
   - 勾选这一行左侧的复选框（**不勾不会烧**，这是最常见的坑）
4. SPIDownload 页里：
   - `SPEED`：`40MHz`（不稳定就降到 20MHz）
   - `FLASH SIZE`：`32Mbit`（= 4MB）
   - COM：选你的端口，`BAUD`：`921600` 或 `460800`
5. 点 **START**，等进度条走完出现 `FINISH`。

## 6. 烧完怎么确认成功

1. 串口日志（115200）应出现：

```
=== Tang 60K ESP32 Console v2.0.0 ===
UART2: TX=GPIO17 RX=GPIO16 @ 115200 8N1
[SC] LittleFS ok, used=... / total=... bytes
[AP] started -> 192.168.4.1
[AP] SSID=Tang60K-Music PASS=tang60k2026
Open http://192.168.4.1/ on your phone
```

2. 手机能搜到 WiFi **`Tang60K-Music`**；
3. 连上后浏览器打开 `http://192.168.4.1/`，页面右上角圆点变绿。

以上三条都出现 = 烧录与固件启动都正常。

## 7. 常见报错

| 报错 | 原因 | 处理 |
|---|---|---|
| `Failed to connect to ESP32: Timed out waiting for packet header` | 没进下载模式、或被别的程序占用串口 | 关掉串口监视器/其他终端；按住 **BOOT** 键，点一下 **EN/RST**，松开 BOOT，再烧 |
| `could not open port 'COM5': Permission denied` | 串口被占用 | 关闭 `pio device monitor`、VS Code 串口监视器、其它 IDE |
| `A fatal error occurred: Invalid head of packet` | 波特率太高 | `--baud 115200` 重试 |
| `Error 1` 但代码没错，且发生在命令行 | `PYTHONPATH` shim | `$env:PYTHONPATH=''` 后重试 |
| 烧完不断重启，日志 `rst:0x10 (RTCWDT_RTC_RESET)` | 分区表与 Flash 大小不匹配 | 先 `pio run -t erase` 全片擦除，再重烧 |
| `[SC] LittleFS mount FAILED` | LittleFS 分区未格式化 | 代码里 `LittleFS.begin(true)` 会自动格式化；若仍失败，先 `pio run -t erase` |
| 手机连上热点但打不开页面 | 手机切回了移动数据 | 关闭「智能网络切换 / WLAN+ / 私有 DNS」，或飞行模式后只开 WiFi |

## 8. 擦除与回滚

```powershell
$env:PYTHONPATH=''
pio run -t erase          # 全片擦除（会清掉 LittleFS 里的曲谱）
pio run -t upload         # 重新烧
```

回滚到旧固件：把旧的 `firmware.bin` 用 `write_flash 0x10000 old_firmware.bin` 烧回即可（分区表没变的话）。

---

## 9. 烧录时的接线注意

- 烧录只用 ESP32 的 USB 线，**FPGA 侧 UART 线可以一直连着**，不影响烧录。
- 但烧录瞬间 ESP32 会复位，若 FPGA 正在跑，可能收到半帧垃圾字节 → FPGA 侧会置 `frame_error`，属正常现象，复位一次即恢复。
- 反过来：给 FPGA 重新下载位流时，ESP32 不用断电。

## 10. 本机已验证的事实

| 事实 | 依据 |
|---|---|
| `firmware.bin` / `bootloader.bin` / `partitions.bin` 均由 `pio run` 生成 | 本机 `.pio\build\esp32dev\` 实际存在这三个文件 |
| `boot_app0.bin` 存在于 framework 包 | 本机 `~\.platformio\packages\framework-arduinoespressif32\tools\partitions\boot_app0.bin` 实际存在 |
| esptool 支持 `merge_bin` | `tool-esptoolpy\esptool\__init__.py:577`（版本 4.5.1） |
| 实际烧写结果 | **未验证**：本机未接板 |

ESP32 的 4MB Flash 地址布局（0x1000/0x8000/0xe000/0x10000）来自 Arduino-ESP32 的默认分区方案，与本机 `partitions.bin` 一致；如换过分区表，以 `pio run -t upload -v` 打印的地址为准。
