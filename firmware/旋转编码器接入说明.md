# 旋转编码器接入说明（4 × EC11 无源操作面板）

对应工程：`ProPrj_无源操作面板_2026-11-02.epro2`
固件：3.3.7 起支持

---

## 一、面板里到底是什么

从 `panel.epru` 解析出来的实际内容（不是推测）：

| 项 | 值 |
|---|---|
| 编码器数量 | **4 个** |
| 型号 | **EC11E15244G1**（ALPS 增量式，带按压开关） |
| 封装 | `SW-TH_EC11E15244G1`，插件 5 脚 |
| 信号网络 | `ENC1_A` `ENC1_B` `ENC1_SW` … `ENC4_A` `ENC4_B` `ENC4_SW`，共 **12 根** |
| 公共端 | 全部接 **GND** |
| 电源 | **没有**——面板无源，没有 VCC |
| 上拉电阻 | **没有**——必须由 ESP32 内部提供 |

> 依据：`padNet` 字段共 13 个不同网络（12 信号 + GND），`COMPONENT` 里有 4 个 `EC11E15244G1.1`。

**这一点很重要**：因为面板没有上拉电阻，EC11 的 A/B/SW 都是"另一端接地"的开关。所以 ESP32 侧**必须开内部上拉**，而且只能用**具备内部上拉的引脚**——GPIO34~39 不能用（它们只能输入、没有上拉）。

## 二、接线（3.5.9 定稿表 + 3.5.10 接线自检）

### 唯一正确的一张表

| 编码器 | A | B | SW | 功能 |
|---|---:|---:|---:|---|
| **ENC1**（最左） | **GPIO18** | **GPIO19** | **GPIO34** | 音量 / 静音 |
| **ENC2** | **GPIO23** | **GPIO25** | **GPIO35** | 音色 / 回中 |
| **ENC3** | **GPIO26** | **GPIO27** | **GPIO36** | 定弦 / 换弦 |
| **ENC4**（最右） | **GPIO33** | **GPIO32** | **GPIO39** | 混响 / 旁路 |

按键一律**低电平有效**（按下把 SW 拉到 GND）。

**来源（两条独立证据）**：

1. 转接板 `ProPrj_电源端子转接板'_2026-11-03.epro2` 的 `U1` 符号 Pin Name：
   `pad9=D18 pad10=D19 pad19=D34 / pad15=D23 pad23=D25 pad20=D35 /
   pad24=D26 pad25=D27 pad17=VP(36) / pad21=D32 pad22=D33 pad18=VN(39)`。
   交叉验证：`pad6=ESP_RX=GPIO16`、`pad7=ESP_TX=GPIO17` 与本工程 UART2 一致；
   `pad11/14=IMU_SDA/SCL` 落在 GPIO21/22 与 I2C 一致 —— 说明列序可信。
2. 用户按两个工程的网络标签逐根核对（实板接线依据）。

**唯一有出入的是 ENC4 的 A/B**：符号读出是 `A=D32 / B=D33`，用户核对是 `A=GPIO33 / B=GPIO32`。
按用户表执行。A/B 只决定**旋转方向**，实板若方向相反，改 `DELTA_SIGN` 或对调这两根即可。

### 曾经错在哪（3.5.8 的一版回退，别再用）

3.5.8 曾把表改成"面板 U11 与转接板 H9 网络整组反序"——
即 `ENC1 A=39 B=33 SW=32 / ENC2 A=36 B=27 SW=26 / ENC3 A=35 B=25 SW=23 / ENC4 A=34 B=19 SW=18`，
并把它设成**默认**。那是"假设排线同向压接"推出来的，与实物不符。
实板表现：四个旋钮全错位，转一下触发隔壁的按压动作。**该表和那个二选一宏已彻底删除。**

### SW 四路为什么能工作（GPIO34/35/36/39 没有内部上拉）

转接板已经用 **R1..R4** 把 `ENC1_SW..ENC4_SW` 上拉到 `ESP_3V3`
（原理图 `PAD_NET`：`R1.1=ENC1_SW / R1.2=ESP_3V3`，R2/R3/R4 同构），
所以 **`pinMode(INPUT)` 就够了，不要再自己加电阻**。
驱动里 `configPin()` 对 `>=34` 的脚用 `INPUT`，其余用 `INPUT_PULLUP`。

### 接线要点

- **两根 GND 都要接**。面板是无源的（无上拉、无电源），SW 的上拉在转接板上。
- 面板座 `HC-2510-14AW-05`，转接板对应 `H9` 同型号母座。
- 插好后先做**接线自检**（3.5.10）：网页「面板接线自检」→「清零后监视」→ 只转最左那颗，
  看哪两个 GPIO 在涨；判读表见下面 2.5 节。脚本等价命令：`python tools\flash_tool.py --encprobe`。
- 再看「面板累计格数」：**转旋钮 1 → ENC1 必须涨，其它三个不动**；
  **按旋钮 1 → 「按键电平」最低位变 0**，松手回 1。

### 接线自检：一次判定排线方向（3.5.10）

排线是 **1-1 直连** 还是 **1<->14 反序**，两个 HC-2510 座的文件里都查不到（取决于压线方式）。
两种接法下四个旋钮**都能动**，只是物理位置整体倒转，所以光看「能不能用」分不出来。

3.5.10 把 12 个编码器 GPIO 各自累计**边沿数**，并新增网页卡片「面板接线自检」+ `/encprobe` 端点：

```
GET /encprobe          -> {"fw":"3.5.10","pins":[18,...],"edges":[...]}
GET /encprobe?clr=1    -> 先清零再读
```

**操作**：点「清零后监视」→ **只转最左那颗旋钮约 5 格**（不按、不转其它）→ 看哪两个数在涨：

| 在涨的 GPIO | 结论 | 动作 |
|---|---|---|
| **18 / 19** | 1<->14 反序排线 | 当前 `kPins` 正确，无需改代码 |
| **32 / 33** | 1-1 同向排线，整组倒转 | 重压一条反序线，或把 `kPins` 改成 `{39,33,32} {36,27,26} {35,25,23} {34,19,18}` |
| **34** | A 与 SW 接反 | 转被当成按压（会莫名换弦/切旁路），查 1A 与 1SW 两根线 |
| 全 0 | 面板没通 | 先查 GND，再查排线是否插到底 |

边沿数是**电平跳变次数**，转 5 格大约各涨 20~40；按一下只涨 2，所以「转」和「按」的计数形状完全不同。

脚本侧一条命令（**走 WiFi，不占串口**，需电脑连 `Tang60K-Music` 热点）：

```
python tools\flash_tool.py --encprobe              # 默认采样 8 秒
python tools\flash_tool.py --encprobe --encwait 12 # 手慢就加长
```

它会自己清零、倒计时、读回 12 个计数并直接给出上表结论。

## 三、旋钮能做什么

分配（固件 **3.5.3** 起；在 `main.cpp` 的 `onEncTurn` / `onEncClick` / `onEncHold` 里，改这里不用碰驱动）：

| 编码器 | 旋转 | 短按 | 长按（1.5 s） |
|---|---|---|---|
| **ENC1** | **音量**，每格 ±20（3.5.13 起，原 ±2） | 静音 / 取消静音 | **参数复位** |
| **ENC2** | **音色倾斜**，每格 ±20（3.5.13 起，原 ±2；−100…+100） | 倾斜回中（0 dB） | **参数复位** |
| **ENC3** | **当前弦音高（音调）**，每格 ±1 半音（**未改**） | **换下一根弦** | **参数复位** |
| **ENC4** | **混响湿声**，每格 ±40（3.5.13 起，原 ±4） | 混响旁路 开/关 | **参数复位** |

> **3.5.13 的灵敏度调整**：按用户要求"除音调外全部拉高 10 倍"，音量 2→20、音色 2→20、湿声 4→40；
> **音调（ENC3 定弦）保持每格 1 半音** —— 半音已是最小音乐单位，×10 会无法调音。
> 四个步长集中在 `main.cpp` 顶部的 `kStepVolume / kStepTilt / kStepTune / kStepWet` 常量里。

**4 个编码器长按都触发同一个参数复位** —— 不然演奏时想复位还得先摸清是哪一颗。

### ENC3：调音高 + 按压换弦

- 旋转 → 只改**当前选中那一根弦**的音高，每格 1 个半音，范围 MIDI 24…96（G1…C7）
- 按压 → 游标走下一根：`琴1 → 琴2 → 琴3 → 琴4 → 尤1 → 尤2 → 尤3 → 尤4 → 琴1`
- 网页「定弦」卡片会**自动跟着切**（state 里的 `tsel` 字段），不会出现"面板在第 3 根、网页还显示第 1 根"
- 走的是**已有的 `SET_TUNE` 命令**（`0x10..0x17`），**FPGA 一个字都没改**

> 为什么是 8 根而不是 4 根：定弦寄存器本来就有 8 条 lane（小提琴 4 + 尤克里里 4）。
> 只转 4 根的话，尤克里里就没法用旋钮调了。按压时串口会打印当前是哪根，例如
> `[enc] tune sel = 4  (uke1)  MIDI 67`

### 长按（任意编码器）= 参数复位

按住 **任意一颗** 1.5 秒触发，恢复成上电默认值并立即重发给 FPGA：

| 参数 | 复位值 |
|---|---|
| 音量 | 128（0 dB），同时解除静音 |
| 音色倾斜 | 0（中） |
| 定弦 | 标准音 `55 62 69 76 67 60 64 69` |
| 混响 | 湿声 64 / 阻尼 128 / 尾音 1 / **旁路（干声）** |

**不重启 ESP32** —— WiFi、网页连接、曲谱进度都不受影响。
只改参数、不重启，所以长按复位不会打断演奏中的连接。

误触风险由 1.5 s 阈值兜底：正常拧旋钮不会按住不动 1.5 秒。
串口会打印是哪一颗触发的：`[enc] long-press ENC2 -> param reset`。

### 相对旧版的映射变化

| 编码器 | 旧（3.3.7~3.5.1） | 新（3.5.3） |
|---|---|---|
| ENC3 旋 | 混响湿声 | **当前弦音高** |
| ENC3 按 | 混响旁路 | **换下一根弦** |
| ENC4 旋 | 混响阻尼 | **混响湿声**（从 ENC3 搬来） |
| ENC4 按 | 查询 FPGA 状态 | **混响旁路**（从 ENC3 搬来） |
| ENC1/2/3/4 长按 | 无 | **参数复位**（新增，4 颗都能触发） |

阻尼（damp）从 3.5.2 起只在网页上调；面板不再占一档。

### 和手机的关系：同一份数据，不是两套（3.5.5 修正）

**能同步到什么程度：数值始终一致；旋钮的物理角度不会跟着网页走。**

EC11 是**增量式**编码器 —— 没有绝对位置、没有限位，它只能报"转了 +1 格"。
所以网页上把滑块拖到 50%，旋钮的物理转角不会自动转过去；反过来转旋钮，
网页滑块和数字会立刻跟到同一个值。这是器件原理决定的，所有增量编码器都这样。

#### 同步矩阵（3.5.5 实测过的字段）

| 参数 | 面板 → 网页 | 网页 → 面板 | state 字段 |
|---|:---:|:---:|---|
| 音量 | ✅ | ✅ | `vt`（目标值） |
| 静音 | ✅ | ✅ | `mut` |
| 音色倾斜 | ✅ | ✅ | `tilt` |
| 定弦 8 条 | ✅ | ✅ | `tn` |
| 当前弦（游标） | ✅ | ✅ | `tsel` |
| 混响湿声 | ✅ | ✅ | `wet` |
| 混响阻尼 | 面板不控 | ✅ | `damp` |
| 尾音 | ✅ | ✅ | `tail` |
| 混响旁路 | ✅ | ✅ | `bp` |

#### 3.5.5 修掉的两个不同步

**① 音量滑块纹丝不动**（`web_ui.h` 原第 236 行）

```js
if(m.link && m.vol!==undefined){ el('volV').textContent=volText(m.vol); }
```

三个问题叠在一起：

- 只改数字，`el('vol').value` 从来没被面板旋钮改过
- 用的是 `m.vol`（FPGA 状态**回读**值，5 Hz 才刷一次）
- 被 `m.link` 挡住，链路一断就彻底不更新

改成用 `m.vt`（ESP32 的**目标**值 `gVolTarget`），滑块和数字一起更新。

**② 尾音滑块只在连接时同步一次**，之后周期推送不更新 —— 长按复位后网页还停在旧值。

#### 3.5.5 修掉的一个音量 bug

```cpp
// 原来
int v = (int)gVolTarget + (int)d * 2;   // 静音时 gVolTarget 已经是 0
```

按过静音之后再转音量，是从 **0 开始涨**（0→2→4…），这个量级根本听不见，
表现就是"音量旋钮转了没反应"。改成静音态下从 `gVolBeforeMute` 起步。

#### 顺带加的两个接线诊断（网页「定弦」卡片里）

| 显示 | 含义 | 判断方法 |
|---|---|---|
| `面板累计格数 ENC1/2/3/4 = a / b / c / d` | 每路转过多少格 | 转哪一颗，对应位置必须涨；不涨 = 那一路 A/B 没通 |
| `按键电平 ENC1/2/3/4 = 1 / 1 / 1 / 1` | 每路 SW 的当前电平 | 静置必须全是 1；某位是 0 = 那一路 SW 接到 GND 或接错 |

旋钮和网页**共用同一套内部变量**（`gVolTarget` / `gTilt` / `gWet` / `gDamp` / `gBypass`），所以：

- 转旋钮 → 网页滑块会跟着动（3.3.7 在 `pushState` 里新增了 `tilt/wet/damp/tail/bp` 字段）
- 拖手机 → 旋钮的基准值同步变化，不会"各记一套、互相打架"
- 你正在拖某条滑块时，那一条不会被旋钮的值覆盖（`document.activeElement` 判断）

音量的下发给终走**软斜坡**（每 2 ms 一小步），所以转得再快也不会有 click。

## 五、实现方式与技术取舍

| 项 | 选择 | 理由 |
|---|---|---|
| 采样 | **1 ms 定时轮询**，不用中断 | 4 路 × 2 相 = 8 个边沿源，机械抖动会造成中断风暴，拖慢 WiFi 和 5 Hz 的 FPGA 轮询。手拧最快约 100 格/秒，一格 4 象限 ≈ 2.5 ms/象限，1 ms 采样足够 |
| 解码 | **正交查表**（16 项）| 只有 4 个有效转移给 ±1，其余记 0，机械抖动被自然吸收，不需要额外的延时消抖 |
| 计数 | 累积象限，**±4 算一格**，余数保留 | 不丢细分，慢转也不漏格 |
| 按键 | **20 ms 稳定判定**；**松手沿**才发短按，按住到 1.5 s 发长按 | 避免抖动连击；按下沿就发短按的话，长按会先误触发一次短按动作（例如先切了混响旁路） |
| 阻塞 | 全程非阻塞 | 不破坏 20 Hz 状态推送与录音 |

### 上电后怎么确认

1. 先做 2.5 节的**接线自检**，确认真在动的是哪两个脚（这一步决定下面几步是否有意义）
2. 转 ENC1（最左），网页「面板累计格数」**只有 ENC1 涨**，音量数字跟着变，喇叭音量平滑变化
2. 按 ENC1，网页「按键电平」最低位变 0，应当静音；再按恢复原值
3. 转 ENC2，`tilt` 滑块跟着动，音色变亮/变暗；**不应该触发换弦**
4. **如果转一格跳两格或方向反了**：先看 `DELTA_SIGN`，再确认 A/B 有没有接反
5. **如果完全无反应**：先确认 GND 有没有接（最常见），再量 SW 脚在按下时是否到 0 V
